# 充电动画功能说明

## 目标

插入充电器时，宠物页面自动播放一次 `charge.mjpeg` 充电动画；播放完毕后，自动恢复 `neutral.mjpeg` 循环播放。拔出充电器则不额外触发任何动画切换。

---

## 背景：充电状态检测硬件

硬件上有两个充电状态 GPIO：

| GPIO | 信号名 | 说明 |
|---|---|---|
| `CHARGING_GPIO` | CHRG | 低电平 = 正在充电 |
| `DONE_GPIO` | DONE | 低电平 = 充电完成 |

`DesktopPetBoard::GetBatteryLevel()` 通过读取这两个 GPIO 电平判断充电状态：

```cpp
// charging = true 的条件：CHRG=0（低），DONE=1（高）
if (charge_level == 0 && done_level == 1) {
    charging = true;
}
```

---

## 整体数据流

```
电池定时器（ESP timer 任务，每 1.5s）
  │
  ├── GetBatteryLevel() 读取 GPIO 充电状态
  ├── 检测状态变化（上升沿：未充电 → 充电）
  │
  └── pet_page_notify_charging(true)      ← 线程安全：仅写原子标志
        │
        ▼
      s_charge_start_pending = true       ← std::atomic<bool>，跨任务安全

指示灯定时器（LVGL 任务，每 500ms）
  │
  ├── 检测 s_charge_start_pending
  │
  └── start_charge_anim()
        │
        ├── file_exists("/sdcard/mjpeg/charge.mjpeg")
        ├── close_decoder()               ← 释放当前动画资源
        ├── open_mjpeg("charge.mjpeg")    ← 打开充电动画文件
        ├── s_gif.one_shot = true         ← 标记为单次播放
        └── 解码第一帧并显示

MJPEG 帧定时器（LVGL 任务，每 100ms，10fps）
  │
  ├── mjpeg_next_frame()
  │     ├── 正常帧：解码 → 显示（同普通动画）
  │     └── EOF（文件末尾）且 one_shot == true
  │           └── one_shot_done = true，return false（不 rewind）
  │
  └── 检测 one_shot_done == true
        │
        └── switch_to_neutral()
              ├── close_decoder()
              ├── open_mjpeg("neutral.mjpeg")
              ├── s_gif.one_shot = false    ← 恢复循环模式
              └── 解码第一帧，恢复定时播放
```

## 代码详解

### 1. `pet_gif_t` 新增字段

```cpp
// ui_pet.cc
typedef struct {
    // ... 原有字段 ...
    bool  one_shot;       // 单次播放，播完后切回 neutral
    bool  one_shot_done;  // 单次播放已到达 EOF
} pet_gif_t;
```

- `one_shot = true`：当前播放为"单次模式"，到 EOF 不 rewind
- `one_shot_done = true`：到达 EOF 后设置，通知 `timer_cb` 执行切换

### 2. 跨线程通信：原子标志

```cpp
// ui_pet.cc
static std::atomic<bool> s_charge_start_pending{false};
```

电池定时器运行在 ESP timer 任务（非 LVGL 任务），不能直接操作 LVGL 对象。使用 `std::atomic<bool>` 作为跨任务信号：

- **写**：电池定时器调用 `pet_page_notify_charging(true)` → `store(true)`
- **读/清**：指示灯定时器（LVGL 任务）调用 `exchange(false)` 原子读取并清零

### 3. `desktop_pet.cc` — 检测充电上升沿

```cpp
static void BatteryTimerCallback(void* arg) {
    static bool last_charging = false;
    auto* board = static_cast<DesktopPetBoard*>(arg);

    // 每次回调（1.5s）检测充电状态
    int level;
    bool charging = false, discharging = false;
    board->GetBatteryLevel(level, charging, discharging);

    if (charging != last_charging) {
        last_charging = charging;
        pet_page_notify_charging(charging);  // 仅设置原子标志，线程安全
    }

    // 每 10 次（15s）更新电压和百分比
    if (++timer_count >= 10) {
        board->UpdateBatteryStatus();
        timer_count = 0;
    }
}
```

**解读**：
- 每 1.5s 读一次充电 GPIO，开销极低
- 仅在状态**变化时**通知，避免重复触发
- `last_charging` 是函数内的 `static` 局部变量，只被本函数（同一任务）访问，无需同步

### 4. `pet_page_notify_charging()` — 线程安全通知

```cpp
void pet_page_notify_charging(bool charging) {
    static bool was_charging = false;
    if (charging && !was_charging) {
        // 上升沿：插入充电器
        s_charge_start_pending.store(true, std::memory_order_relaxed);
        ESP_LOGI(TAG, "charging started → schedule charge anim");
    }
    was_charging = charging;
}
```

**解读**：
- 只响应"从未充电变为充电"的上升沿，拔出充电器不触发任何动画
- 仅写原子变量，可安全从任意任务调用

### 5. `indicator_update_cb()` — LVGL 任务内消费标志

```cpp
static void indicator_update_cb(lv_timer_t *) {
    // 检查是否有待处理的充电动画请求
    if (s_charge_start_pending.exchange(false, std::memory_order_relaxed)) {
        if (s_gif.loaded && !s_gif.paused) {
            start_charge_anim();
        }
    }
    // ... 原有指示灯逻辑 ...
}
```

**解读**：
- `exchange(false)` 原子地读取并清零，避免重复执行
- 只在页面已加载（`loaded`）且未暂停（`!paused`）时播放，防止 SD 卡未就绪时崩溃

### 6. `start_charge_anim()` — 启动充电动画

```cpp
static void start_charge_anim() {
    if (!file_exists(kChargeMjpeg)) {
        ESP_LOGW(TAG, "charge.mjpeg not found, skip charge anim");
        return;
    }
    // 避免重复启动同一动画
    if (s_gif.one_shot && strcmp(s_current_gif_path, kChargeMjpeg) == 0) return;

    close_decoder();
    if (s_gif.timer) lv_timer_pause(s_gif.timer);

    if (open_mjpeg(kChargeMjpeg)) {
        snprintf(s_current_gif_path, sizeof(s_current_gif_path), "%s", kChargeMjpeg);
        s_gif.one_shot = true;
        s_gif.one_shot_done = false;
        bool ok = mjpeg_next_frame() && decode_current_jpeg_to_rgb565();
        if (ok) {
            show_status(false);
            lv_timer_resume(s_gif.timer);
            lv_timer_reset(s_gif.timer);
        } else {
            switch_to_neutral();  // 解码失败则回退
        }
    }
}
```

### 7. `mjpeg_next_frame()` — EOF 处理修改

```cpp
if (feof(s_gif.fp)) {
    if (s_gif.one_shot) {
        // 单次模式：到末尾不 rewind，通知上层切换
        s_gif.one_shot_done = true;
        return false;
    }
    // 循环模式：正常 rewind
    rewind(s_gif.fp);
    clearerr(s_gif.fp);
    s_gif.in_frame = false;
    s_gif.prev_byte = 0;
    s_gif.jpeg_len = 0;
    continue;
}
```

### 8. `timer_cb()` — 检测单次播放结束

```cpp
static void timer_cb(lv_timer_t *t) {
    // ...
    if (!mjpeg_next_frame()) {
        if (s_gif.one_shot_done) {
            ESP_LOGI(TAG, "charge anim ended, switching to neutral");
            switch_to_neutral();
        }
        return;
    }
    decode_current_jpeg_to_rgb565();
}
```

### 9. `switch_to_neutral()` — 切回循环动画

```cpp
static void switch_to_neutral() {
    close_decoder();
    if (open_mjpeg(kFallbackMjpeg)) {
        snprintf(s_current_gif_path, sizeof(s_current_gif_path), "%s", kFallbackMjpeg);
        s_gif.one_shot = false;
        s_gif.one_shot_done = false;
        bool ok = mjpeg_next_frame() && decode_current_jpeg_to_rgb565();
        if (ok) {
            show_status(false);
            if (!s_gif.paused && s_gif.timer) {
                lv_timer_resume(s_gif.timer);
                lv_timer_reset(s_gif.timer);
            }
        }
    }
}
```

## SD 卡目录结构

```
SD 卡根目录/
└── mjpeg/
    ├── neutral.mjpeg    ← 默认循环动画（开机加载）
    ├── charge.mjpeg     ← 充电动画（单次播放）★ 新增
    ├── happy.mjpeg
    ├── sad.mjpeg
    └── ...（其他表情动画）
```

> `charge.mjpeg` 不存在时，功能会**静默跳过**（打印 WARN 日志），不影响其他动画正常播放。

---

## 关键设计决策

### 为什么用 `std::atomic<bool>` 而不是 `DisplayLockGuard`？

电池定时器运行在 ESP timer 内部任务，调用 `DisplayLockGuard::Lock()` 会阻塞等待 LVGL 锁，存在死锁风险。原子变量的写操作是无锁的，不会阻塞 ESP timer 任务，更安全。

消费端在 `indicator_update_cb`（每 500ms，LVGL 任务内），已天然处于正确的 LVGL 上下文，无需加锁。

### 为什么在 `indicator_update_cb` 消费而不是单独建一个定时器？

`indicator_update_cb` 已有的 500ms 轮询频率对充电检测足够（最坏延迟 500ms），复用它避免了创建额外的 LVGL timer，减少资源消耗。

### 为什么只响应上升沿（插入），不响应下降沿（拔出）？

- **拔出时**：如果正在播放 `charge.mjpeg`，让它自然播完再切回 neutral，体验更流畅，不会出现动画突然中断的情况
- **如需立即切换**：可扩展 `pet_page_notify_charging(false)` 的逻辑，添加 `s_charge_stop_pending` 原子标志

### 为什么 `one_shot_done` 和 `one_shot` 分两个字段？

`one_shot` 表示"意图"（这条动画是否为单次播放），`one_shot_done` 表示"事件"（已到达 EOF）。分开设计使得 `mjpeg_next_frame()` 只负责检测 EOF 并发出信号，`timer_cb` 负责响应并执行切换，职责清晰。
