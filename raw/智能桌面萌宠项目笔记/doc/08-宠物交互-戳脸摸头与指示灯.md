## 目标

- **戳脸（屏幕点击）** 与 **摸头（GPIO4 触摸传感器）** 能触发宠物的语音反馈，并与当前对话状态自然衔接。
- 在宠物页面右上角新增一个 **状态指示灯圆点**，用颜色/光晕区分空闲、聆听、说话、连接中等状态。

---

## 整体交互设计

### 1. 戳脸 & 摸头的行为规则

- **空闲状态 (`kDeviceStateIdle`)**
  - 戳脸 / 摸头：
    - 打开音频通道 → 进入聆听模式。
    - 发送 `listen/detect` 消息，文本为 `"戳脸"` 或 `"摸头"`。
    - LLM 收到文本后立刻语音回应（例如“摸头好舒服呀～”）。
    - 回到 **聆听状态**，用户可以继续说话。
- **聆听状态 (`kDeviceStateListening`)**
  - 戳脸 / 摸头：**停止聆听，关闭音频通道，回到空闲**（相当于“结束本轮对话”）。
- **说话状态 (`kDeviceStateSpeaking`)**
  - 戳脸 / 摸头：**打断当前播报**，调用 `AbortSpeaking`，回到聆听（可继续说话）。
- **连接中 (`kDeviceStateConnecting`)**
  - 戳脸 / 摸头：忽略，避免状态机混乱。

### 2. 为什么采用 `listen/detect` 文本注入

之前尝试过两种设计：

- **MCP `notifications/message` / `tools/call`**
  - 设备发送 MCP 通知或工具调用给云端。
  - 实测发现：服务器不会把这些消息自动注入 LLM 对话上下文，几乎不会触发语音回复。
- **自定义 `type:"stt"` 消息**
  - 文档中 `stt` 是 **服务端→设备** 用来下发转写文本，不适合作为设备→服务端的通道。

最终方案：

- 使用协议中已经定义好的 **`listen/detect` 消息**：

```json
{
  "type": "listen",
  "state": "detect",
  "text": "摸头"
}
```

- 服务器原本用它来传递“唤醒词被检测到”的事件；这里复用 `text` 字段，把 `"摸头"` / `"戳脸"` 当作“虚拟唤醒词”，LLM 就可以自然地用语音回应这些动作。

## 代码实现：核心入口 `TriggerPetInteraction`

### 1. Application 层统一入口

文件：`main/application.h`

- 新增接口：

```cpp
void TriggerPetInteraction(const std::string& text);
```

文件：`main/application.cc`

- 统一处理戳脸/摸头的 **状态切换 + 文本注入** 逻辑：

```cpp
void Application::TriggerPetInteraction(const std::string& text) {
    Schedule([this, text]() {
        if (!protocol_) return;
        auto state = GetDeviceState();

        if (state == kDeviceStateIdle) {
            // 空闲 → 注入动作文本，宠物立即语音回应，之后保持聆听
            ESP_LOGI(TAG, "TriggerPetInteraction: idle → inject '%s'", text.c_str());
            SetDeviceState(kDeviceStateConnecting);
            if (!protocol_->OpenAudioChannel()) {
                return;
            }
            play_popup_on_listening_ = true;
            SetListeningMode(aec_mode_ == kAecOff ? kListeningModeAutoStop : kListeningModeRealtime);
            // 等聆听建立后再发送 detect，确保音频管道就绪
            Schedule([this, text]() {
                if (GetDeviceState() == kDeviceStateListening && protocol_) {
                    protocol_->SendWakeWordDetected(text);
                }
            });
        } else if (state == kDeviceStateListening) {
            // 聆听中 → 停止，回到空闲
            ESP_LOGI(TAG, "TriggerPetInteraction: listening → stop");
            text_chat_phase_ = 0;
            protocol_->CloseAudioChannel();
        } else if (state == kDeviceStateSpeaking) {
            // 播报中 → 打断，回到聆听
            ESP_LOGI(TAG, "TriggerPetInteraction: speaking → abort");
            AbortSpeaking(kAbortReasonNone);
        }
        // 连接中：忽略
    });
}
```

关键点：

- **空闲时**：
  - 打开音频通道 → 设置聆听模式 → 等状态机真正进入 `listening` 后，再异步发送 `SendWakeWordDetected(text)`。
  - 避免服务器 TTS 音频过快到达被 `ResetDecoder()` 清空的问题（之前遇到过“只看到文字，没有声音”的 bug）。
- **聆听中**：关闭通道，相当于“结束本轮对话”。
- **说话中**：调用 `AbortSpeaking()`，打断当前播报。

## 摸头：GPIO4 触摸传感器

文件：`main/boards/desktop-pet/touch.h`

- 引脚定义与初始化接口：

```cpp
#define HEAD_TOUCH_GPIO GPIO_NUM_4
void head_touch_init(void);
```

文件：`main/boards/desktop-pet/touch.cc`

### 1. GPIO 配置与采样任务

```cpp
// 触发电平：大部分电容触摸模块"触碰=LOW"，如果模块相反可改为 1
static constexpr int kTouchActiveLevel = 0;
static constexpr int kDebounceCount    = 3;      // 3×20ms ≈ 60ms 消抖
static constexpr uint32_t kCooldownMs  = 1000;   // 1s 冷却

static uint32_t s_last_trigger_ms = 0;

static void send_touch_notification(const char *action, const char *text) {
    ESP_LOGI(TAG, ">>> %s → TriggerPetInteraction", action);
    Application::GetInstance().TriggerPetInteraction(text);
}

static void head_touch_task(void *arg) {
    int stable_count = 0;
    bool was_active = false;

    int init_level = gpio_get_level(HEAD_TOUCH_GPIO);
    ESP_LOGI(TAG, "GPIO%d 初始电平=%d (期望空闲=%d, 触摸=%d)",
             HEAD_TOUCH_GPIO, init_level,
             !kTouchActiveLevel, kTouchActiveLevel);

    while (true) {
        int level = gpio_get_level(HEAD_TOUCH_GPIO);
        bool active = (level == kTouchActiveLevel);

        if (active) {
            if (stable_count < kDebounceCount) stable_count++;
        } else {
            stable_count = 0;
        }

        bool is_touched = (stable_count >= kDebounceCount);

        // 上升沿触发：从"未触摸"→"触摸"
        if (is_touched && !was_active) {
            uint32_t now = xTaskGetTickCount() * portTICK_PERIOD_MS;
            if (now - s_last_trigger_ms > kCooldownMs) {
                s_last_trigger_ms = now;
                send_touch_notification("用户摸了你的头", "摸头");
            } else {
                ESP_LOGD(TAG, "cooldown 中，跳过");
            }
        }
        was_active = is_touched;

        vTaskDelay(pdMS_TO_TICKS(20));
    }
}

void head_touch_init(void) {
    gpio_config_t io_conf = {};
    io_conf.pin_bit_mask  = (1ULL << HEAD_TOUCH_GPIO);
    io_conf.mode          = GPIO_MODE_INPUT;
    io_conf.pull_up_en    = GPIO_PULLUP_ENABLE;
    io_conf.pull_down_en  = GPIO_PULLDOWN_DISABLE;
    io_conf.intr_type     = GPIO_INTR_DISABLE;
    gpio_config(&io_conf);

    xTaskCreate(head_touch_task, "head_touch", 3072, nullptr, 2, nullptr);
    ESP_LOGI(TAG, "摸头传感器已初始化 (GPIO%d, 触发电平=%d)", HEAD_TOUCH_GPIO, kTouchActiveLevel);
}
```

初始化位置：

- 在 `main/boards/desktop-pet/desktop_pet.cc` 的 `DesktopPetBoard` 构造函数中调用 `head_touch_init()`，确保上电后后台任务开始轮询摸头状态。

## 问题排查与演进过程

### 1. 没有语音播报的问题

现象：

- 日志中可以看到：
  - `Application: >> 摸头`
  - `Application: << 好舒服呀，谢谢你的抚摸...`
- 但完全没有 `AudioCodec: Set output enable to true`，听不到任何声音。

原因分析：

- 之前的实现是 **先发送 `SendWakeWordDetected(text)`，再调用 `SetListeningMode()`**。
- 服务器对 `"摸头"` 文本响应太快，TTS 音频到达时：
  - 设备刚好从 `listening → speaking`，`HandleStateChangedEvent` 中调用了 `audio_service_.ResetDecoder()`。
  - 早到的音频包被清空，后面也没有新的音频，导致“只看见文字，没有声音”。

解决：

- 统一改为：
  - **先进入 `listening`，再异步发送 `detect`**（见上面 `TriggerPetInteraction` 内的第二个 `Schedule`）。
  - 同时利用 `play_popup_on_listening_` 在第一次进入 `listening` 后播放提示音，提前激活音频输出硬件。

### 2. 会话无法结束的问题

一开始尝试过“自动关闭通道”的方案（使用 `text_chat_phase_` 标记“下一次进入 listening 时关闭音频通道”），但体验不好：

- 宠物说完“摸头好舒服呀”后立刻回到空闲，用户想继续说话必须重新唤醒。

最终方案：

- **戳脸/摸头之后仍然保持在聆听状态**：
  - 让宠物先说一句“被戳/被摸”的反馈。
  - 然后继续聆听用户说话，整个体验更像“正在聊天时顺手摸了摸头”。
  - 用户不想继续说话时，再次戳脸/摸头即可结束当前会话。

### 3. MCP 工具是否有必要

曾经在 `desktop_pet.cc::InitializeTools()` 中为 MCP 注册过：

- `self.pet.poke_face`
- `self.pet.pat_head`

实现只是简单返回一段文本：

```cpp
[](const PropertyList&) -> ReturnValue {
    return std::string("用户戳了你的脸");
}
```

问题：

- 这些工具并不真正控制硬件，只是把“动作发生了”转成一句文本返回给 LLM。
- 现在动作文本已经通过 `listen/detect` 直接送给 LLM，这些 MCP 工具变成了 **完全冗余** 的通道。

最终：

- 保留 `self.led.on_clock` 等真正操作设备的 MCP 工具。
- 删除 `self.pet.poke_face` / `self.pet.pat_head` 注册，避免让 LLM看到但永远不调用的“伪能力”。

## 宠物页右上角状态指示灯

### 1. 设计方案

- 屏幕分辨率：**280×240**，GIF 全屏播放。
- 指示灯：
  - 位置：**右上角，距边 10px**。
  - 尺寸：**12×12 px** 圆形。
  - 表现：
    - 空闲：深灰色，半透明，不抢风头。
    - 聆听：亮绿色，带光晕。
    - 播报：亮蓝色，带光晕。
    - 连接中：橙色，500ms 闪烁。

### 2. LVGL 实现

文件：`main/boards/desktop-pet/ui/ui_pet.cc`

#### （1）全局对象与定时器

```cpp
// ── 状态指示灯 ────────────────────────────────────────────────────────
static lv_obj_t   *s_indicator       = nullptr;
static lv_timer_t *s_indicator_timer = nullptr;
static bool        s_blink_state     = false;

static void indicator_update_cb(lv_timer_t *) {
    if (!s_indicator) return;

    auto state = Application::GetInstance().GetDeviceState();
    s_blink_state = !s_blink_state;

    lv_color_t color;
    lv_opa_t   opa;
    int        shadow_w;

    switch (state) {
        case kDeviceStateListening:
            color    = lv_color_make(0, 210, 90);      // 绿色
            opa      = LV_OPA_COVER;
            shadow_w = 10;
            break;
        case kDeviceStateSpeaking:
            color    = lv_color_make(70, 145, 255);    // 蓝色
            opa      = LV_OPA_COVER;
            shadow_w = 10;
            break;
        case kDeviceStateConnecting:
            color    = lv_color_make(255, 165, 0);     // 橙色（闪烁）
            opa      = s_blink_state ? LV_OPA_COVER : LV_OPA_40;
            shadow_w = s_blink_state ? 8 : 0;
            break;
        default:                                      // 空闲：暗灰低调
            color    = lv_color_make(60, 60, 60);
            opa      = LV_OPA_50;
            shadow_w = 0;
            break;
    }

    lv_obj_set_style_bg_color(s_indicator, color, 0);
    lv_obj_set_style_bg_opa(s_indicator, opa, 0);
    lv_obj_set_style_shadow_width(s_indicator, shadow_w, 0);
    if (shadow_w > 0) {
        lv_obj_set_style_shadow_color(s_indicator, color, 0);
        lv_obj_set_style_shadow_opa(s_indicator, LV_OPA_60, 0);
        lv_obj_set_style_shadow_spread(s_indicator, 2, 0);
    }
}
```

#### （2）在宠物界面创建指示灯


特点：

- 完全封装在 `ui_pet.cc` 中，不影响聊天页 UI。

- 使用 `LV_OBJ_FLAG_EVENT_BUBBLE` 保证指示灯不会阻挡戳脸点击事件。

## 小结

- **戳脸/摸头**：
  - 底层输入分别来自 LVGL 触摸事件与 GPIO4 传感器。
  - 上层统一通过 `Application::TriggerPetInteraction(text)` 处理，既负责状态切换，又负责通过 `listen/detect` 将 `"摸头"` / `"戳脸"` 文本注入 LLM，对话自然延续。
- **主要坑点**：
  - 发送 `detect` 的时机必须在音频管道稳定之后，否则容易出现“有文字没声音”的情况。
  - MCP 工具只适合作为“LLM 控制设备”的通道，不适合把设备事件绕一圈再返回给 LLM。
- **状态指示灯**：
  - 通过一个简单的 LVGL 圆点+定时器，在 280×240 的宠物页右上角直观展示当前语音状态，配合 GIF 表情形成统一的交互反馈体验。

## 五、MCP 工具：切换回宠物界面（`self.pet.show_pet`）

### 5.1 需求背景

设备有多个页面（宠物页、时钟页、聊天页等），用户在聊天中说"回到宠物"/"看宠物"时，LLM 可以主动调用此工具跳回宠物页面，与 `self.led.on_clock`（跳时钟页）完全对称。

### 5.2 实现步骤

**Step 1：在 `action.cc` 中添加 `ai_pet()` 函数**

```cpp
void ai_pet() {
    lvgl_port_lock(0);
    lv_scr_load(objects.main);   // objects.main 即宠物页 screen
    lvgl_port_unlock();
}
```

**Step 2：在 `actions.h` 中声明**

```cpp
extern void ai_pet();
```

**Step 3：在 `desktop_pet.cc` 的 `InitializeTools()` 中注册**

```cpp
mcp_server.AddTool("self.pet.show_pet",
    "切换到宠物界面。当用户说回到宠物、宠物模式、看宠物等类似意图时调用。",
    PropertyList(),
    [](const PropertyList&) -> ReturnValue {
        ESP_LOGI("desktop-pet", "切换到宠物界面");
        ai_pet();
        return true;
    });
```

### 5.3 注意事项

- `objects.main` 在 `ui_pet.cc` 的 `create_screen_pet_page()` 中赋值，即宠物页 screen 对象。
- `lv_scr_load` 会触发 `LV_EVENT_SCREEN_UNLOADED` / `LV_EVENT_SCREEN_LOADED`，宠物页的 `pet_page_event_cb` 监听这两个事件，切回时 GIF 动画会自动恢复播放。
- 如需带过渡动画，可改用：`lv_screen_load_anim(objects.main, LV_SCR_LOAD_ANIM_MOVE_RIGHT, 300, 0, false)`。
- MCP 工具描述字符串中**不要使用全角引号**（`"` `"`），否则 GCC 会将其解析为字符串边界，导致编译报错：`inconsistent user-defined literal suffixes`。
