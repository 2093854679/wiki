## 闹钟响铃移植说明（铃声播放打通）

本文记录在 `xiaozhi-esp32-main-v2/xiaozhi-esp32` 中，将你从外部仓库复制过来的 `main/alarm` 闹钟逻辑 **接入现有音频播放链路**，实现“闹钟触发后循环播放铃声，直到手动清除”为止。

- **目标**：`GeneralTimer` 触发闹钟 → 设备开始响铃（播放铃声）→ 调用清除接口后停止重复播放
- **复用现有能力**：工程自带 `AudioService::PlaySound()`，可播放固件内嵌的 `.ogg`（Ogg 容器内 Opus）
- **铃声来源**：`scripts/p3_tools/ringtone.mp3`

#### 1.4 更新：`main/application.cc`

把 `SetAlarmEvent()` 发出的事件真正落地为“播放铃声并周期重播”。

- **新增：创建响铃定时器**
  - 在 `Application::Application()` 里 `esp_timer_create()` 一个 `alarm_ring_timer_handle_`
  - 定时器回调不直接操作音频，而是用 `Schedule(...)` 把播放动作投递到主任务，避免音频操作并发

- **新增：析构时清理**
  - 在 `~Application()` 里 `esp_timer_stop/delete(alarm_ring_timer_handle_)`

- **新增：主循环事件处理**
  - 在 `Run()` 的 `ALL_EVENTS` 中加入 `MAIN_EVENT_ALARM_RING`
  - 在循环里新增分支：`if (bits & MAIN_EVENT_ALARM_RING) HandleAlarmRingEvent();`

- **新增：响铃控制与播放逻辑（与“先播报后响铃”策略配套）**
  - `SetAlarmEvent()`：`alarm_ringing_ = true;` 并 `xEventGroupSetBits(..., MAIN_EVENT_ALARM_RING)`（进入“响铃状态”）
  - `HandleAlarmRingEvent()`：
    - **只负责启动/刷新周期重播**：每 7 秒重播一次（铃声约 6.5 秒，留一点间隔避免重叠）
    - **不在这里做首次播放**（首次播放由“播报结束后”的状态切换触发，见 2.1/7.3）
  - `ClearAlarmEvent()`：`alarm_ringing_ = false;` 并停止周期定时器（不再触发重播）
  - `StartAlarmAfterSpeaking()`：置位 `alarm_start_after_speaking_`，等设备从 `speaking` 回落到 `listening/idle` 时触发一次 `PlaySound(OGG_RINGTONE)` 并进入周期重播

### 2. 运行时调用链（工作原理）

#### 2.1 触发响铃

1. `GeneralTimer::TimerEventProcess()` 到达触发时间
2. 调用闹钟回调（`GeneralTimer::AlarmDealFunction(...)`，由 payload 提供 message）
3. 回调通过 `Application::Schedule` 在主任务执行统一策略：
   - 屏幕显示提醒文案
   - 置位“播报结束后再开始响铃”（`StartAlarmAfterSpeaking()`）
   - `StartTextChat(message)` 触发小熊播报（云端 TTS）
4. 播报结束后，状态从 `speaking` 回落到 `listening/idle`：
   - 触发一次 `PlaySound(OGG_RINGTONE)`（首次铃声）
   - 并进入“响铃状态”（`SetAlarmEvent()` + `HandleAlarmRingEvent()` 启动周期重播）

#### 2.2 清除响铃

1. 外部调用 `GeneralTimer::ClearRinging()`（或你在 UI/交互里触发）
2. 该函数调用 `Application::ClearAlarmEvent()`
3. `ClearAlarmEvent()` 停止周期重播定时器 → 不再继续“循环响铃”

#### 2.3 语音/摸头打断闹钟

- **摸头打断**：
  - `pet_on_pat()` 中在检测到 `GetAlarmTimer().isRinging()` 时会调用 `GetAlarmTimer().ClearRinging()`，实现“摸头即停闹钟”。
- **唤醒词打断**：
  - `Application::HandleWakeWordDetectedEvent()` 在处理唤醒词事件时，会在检测到 `alarm_ringing_` 后先调用 `GetAlarmTimer().ClearRinging()`，从而实现“说唤醒词先停闹钟，再进入正常对话流程”。

---

### 3. 当前实现的行为与限制

- **循环方式**：每 7 秒重播一次铃声（避免重叠播放，简单可靠）
- **停止行为**：`ClearAlarmEvent()` 会停止后续重播，但不会强制“立刻打断当前正在播放的这一段铃声”
  - 如果需要“立即静音/立刻停播”，建议在 `AudioService` 增加一个 `StopPlayback()` 或 `ClearPlaybackQueue()` 之类的接口，然后在 `ClearAlarmEvent()` 里调用。

### 7. 语音/MCP 设置闹钟与倒计时

闹钟模块已经通过 `GeneralTimer` + NVS 打通，语音设置闹钟/倒计时推荐走 **MCP 工具链路**，而不是在本地解析自然语言。

#### 7.1 MCP 工具列表（`main/mcp_server.cc`）

在 `McpServer::AddCommonTools()` 中新增了 4 个工具：

- `self.get_device_time`
  - **作用**：获取当前设备时间，供上层（LLM）做“相对时间 → 绝对时间”的换算。
  - **参数**：无。
  - **返回 JSON**（对象）：
    - `year, month, day, hour, minute, second, weekday, timestamp`。

- `self.alarm_clock`
  - **作用**：设置“绝对时间”的闹钟（某年某月某日 某时某分某秒响一次）。
  - **参数**：
    - `year`：2020–2100
    - `month`：1–12
    - `day`：1–31
    - `hour`：0–23
    - `minute`：0–59
    - `second`：0–59
    - `message`：字符串，闹钟触发时的提示文本
  - **设备侧实现要点**：
    - 使用 `struct tm` + `mktime` 计算 `time_t trigger_time`。
    - 通过 `GetAlarmTimer().CreateAlarmArg(message)` 创建 payload（内部复制 message；由 `GeneralTimer` 在删除/触发时释放）。
    - 通过全局单例调用：
      - `auto& timer = GetAlarmTimer();`
      - `timer.TimerAddTimerEventAbsolute(trigger_time, E_PET_TIMER_FUNCTION, 1, payload, false);`
      - 其中 `function_id=1` 对应 `GeneralTimer::AlarmDealFunction`，会走统一“先播报后响铃”路径。

- `self.timer_after`
  - **作用**：设置一个“倒计时提醒”，在 `seconds` 秒后响一次（内部仍然走同一条铃声路径）。
  - **参数**：
    - `seconds`：1–604800（最大 7 天）
    - `message`：字符串，倒计时结束时的提示文本
  - **设备侧实现要点**：
    - 通过 `GetAlarmTimer().CreateAlarmArg(message)` 创建 payload。
    - 调用：
      - `auto& timer = GetAlarmTimer();`
      - `timer.TimerAddTimerEventRelative(seconds, E_PET_TIMER_FUNCTION, 1, payload, false);`
    - 同样复用 `GeneralTimer::AlarmDealFunction` 回调。

- `self.alarm_stop_ringing`
  - **作用**：如果当前正在响铃，则立即停止响铃（等价于本地调用 `GetAlarmTimer().ClearRinging()`）。
  - **参数**：无。
  - **返回 JSON**（对象）：`{ ok: true, stopped: true|false }`

#### 7.2 上层（LLM/MCP 客户端）推荐用法

在云端/LLM 侧，可以按照下面的策略使用这三个工具，从而实现“语音设置闹钟/倒计时”：

- **语音设置具体时间闹钟**（例如“明天早上七点叫我起床”）：
  1. 如有需要先调用 `self.get_device_time` 获取当前日期/时间。
  2. 解析用户语义，计算出目标年月日时分秒。
  3. 调用 `self.alarm_clock(year, month, day, hour, minute, second, message)`。

- **语音设置倒计时提醒**（例如“5 分钟后提醒我喝水”）：
  1. 解析自然语言，把“X 分钟/小时后”换算成总秒数 `seconds`。
  2. 调用 `self.timer_after(seconds, message)` 即可。

无论是 `self.alarm_clock` 还是 `self.timer_after`，最终都会统一落到 `GeneralTimer` 里，以 **NVS** 形式持久化，并在到点时通过 `GeneralTimer::AlarmDealFunction` → `StartTextChat`（先播报）→ 状态回落触发首次 `PlaySound(OGG_RINGTONE)` + `HandleAlarmRingEvent()` 周期重播（后响铃）。

#### 7.3 当前“到点行为”策略（保持现状）

目前到点触发的体验为：

- **先播报**：到点后先 `StartTextChat(message)` 触发云端播报提醒文本。
- **后响铃**：播报结束后（状态从 `speaking` 回到 `listening/idle`），开始循环响铃（通过周期重播铃声实现），直到用户打断。
- **打断方式**：
  - 摸头：闹钟响铃中摸头只停止闹钟，不触发“轻摸你头”对话。
  - 唤醒词：闹钟响铃中说唤醒词会先停止闹钟，再进入正常对话流程。
  - MCP：可用 `self.alarm_stop_ringing` 立即停止闹钟。

> 说明：设备端发起播报时使用 `StartTextChat(message)`，其本质是向云端发送 `listen/detect` 文本，因此云端提示词需要对“提醒播报文本”做规则约束，避免再次触发 `self.timer_after/self.alarm_clock` 造成二次定时。

#### 7.4 现象复盘：为什么看起来“到点先响铃”

有时你会在日志里先看到 `XvSenfengTimer: =----ringing----=`，或者在 `listening` 阶段触发了一次铃声播放，让人感觉“到点先响铃”。

- **关键点**：`=----ringing----=` 是闹钟回调触发时打印的日志，不等价于“立即开始播放铃声”。
- **当前实现**：为实现“先播报再一直响”，铃声真正开始播放的位置是在 `Application::HandleStateChangedEvent()`：
  - 当 `alarm_start_after_speaking_` 置位后，设备在从 `speaking` 回落到 `listening/idle` 的状态切换里，会触发一次 `PlaySound(OGG_RINGTONE)` 并启动循环响铃。
- **为什么可能出现在 listening**：
  - 文本播报流程的状态切换包含 `connecting -> listening -> speaking`，以及播报结束后的 `speaking -> listening -> idle`。
  - 因此“启动响铃”可能发生在 `listening`（播报结束回落的中间态）或 `idle`（最终态），这是符合当前策略的正常表现。

#### 6.3 常见错误

- `400 Bad Request - bad time`：
  - 原因：`time` 参数未正确解码或格式不为 `HH:MM`
  - 当前实现已支持 `%3A` 等 URL 编码解码，正常情况下不会再出现该错误。

- `A stack overflow in task httpd has been detected`（设置闹钟后设备重启、Wi-Fi 断开再重连）：
  - 现象：串口打印 `***ERROR*** A stack overflow in task httpd`，随后 `Rebooting...`，重启后 Wi-Fi 重新连接。
  - 原因：HTTP Server 默认任务栈较小（早期为 4096），在 `/api/alarm` 内部调用 `time/localtime/mktime` 等库函数时可能触发栈溢出。
  - 修复：将 `web_server.cc` 中 `httpd_config_t config.stack_size` 增大到 `8192`，为 HTTP 任务留足栈空间。

- `task_wdt: Task watchdog got triggered ... CPU 0: esp_timer`（倒计时触发后偶发 WDT 报错）：
  - 典型日志片段：
    - `XvSenfengTimer: Test callback: 5分钟时间到`
    - 紧接着出现 `task_wdt: Task watchdog got triggered ... CPU 0: esp_timer` 和一串 NVS 相关回溯。
  - 根因：早期实现中，`GeneralTimer::TimerEventProcess()` 在 `esp_timer` 任务上下文里直接调用 `TimerPersistToStorage()` → `Settings::SetString()` → `nvs_set_str()`，闪存读写耗时过长导致 `esp_timer` 任务未及时喂狗。
  - 现有修复方案：
    - 在 `GeneralTimer` 中增加 `pending_persist_` 标志位，所有增删改闹钟只设置该标志，不再在定时器回调中直接写 NVS。
    - `OnClockTimer()` 里检测到 `pending_persist_` 后，通过 `Application::Schedule([this]{ TimerPersistToStorage(); })` 把实际 NVS 落盘放到主任务中异步执行。
    - 这样可以保证：
      - `esp_timer` 任务只做轻量级的内存操作，不再被 NVS 阻塞。
      - 闹钟计划仍然在每次变更后可靠写回 NVS（只是稍有延迟，但对人类感知可忽略）。

### 8. 唤醒词（Wake Word）更换与常见报错

本工程支持 3 种唤醒词实现方式（menuconfig: `Xiaozhi Assistant -> Wake Word Implementation Type`）：

- **Wakenet model with AFE（USE_AFE_WAKE_WORD）**：唤醒词由 Wakenet 模型决定（不是改字符串即可换词）
- **Multinet model (Custom Wake Word)（USE_CUSTOM_WAKE_WORD）**：使用 Multinet 命令词模型，通过配置“自定义唤醒词（拼音）”来更换
- **Disabled**：关闭唤醒词检测

#### 8.1 推荐做法：用 Custom Wake Word 直接换词

1. `idf.py menuconfig`
2. 进入 `Xiaozhi Assistant`：
   - `Wake Word Implementation Type` 选择 `Multinet model (Custom Wake Word)`
   - 填写：
     - `Custom Wake Word`：拼音 + 空格分词（例如 `xiao zhi xiao zhi`）
     - `Custom Wake Word Display`：展示文字（例如 `小智小智`）
     - `Custom Wake Word Threshold (%)`：灵敏度（越小越敏感，默认 20）
3. **关键：选择 Multinet 模型（否则会编译失败）**
   - 在 menuconfig 主界面找到并进入 `ESP Speech Recognition`
   - 找到 `Chinese Speech Commands Model`
   - 把 `None` 改成任意一个 `SR_MN_CN_MULTINET*`（例如 `general chinese recognition (mn7_cn)`）
4. 保存退出后重新编译。

#### 8.2 常见报错：`USE_CUSTOM_WAKE_WORD is enabled but no multinet models are selected`

**现象**（构建 assets 阶段报错）：

- `Error: USE_CUSTOM_WAKE_WORD is enabled but no multinet models are selected in sdkconfig`

**原因**：开启了 `USE_CUSTOM_WAKE_WORD`，但 `ESP Speech Recognition -> Chinese Speech Commands Model` 仍是 `None`（对应 `CONFIG_SR_MN_CN_NONE=y`）。

**修复**：按 8.1 的第 3 步，选中一个 `SR_MN_CN_MULTINET*` 模型后再编译即可。
