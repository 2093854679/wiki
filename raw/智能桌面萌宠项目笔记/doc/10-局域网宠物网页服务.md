## 一、功能概述

本功能在桌面宠物设备上启动一个极简的 HTTP Web 服务器，手机或电脑只要与设备在同一局域网内，就可以通过浏览器访问宠物的当前状态，并进行简单互动（模拟摸头、戳脸、重置养成数据）。

- **实现方式**：使用 ESP-IDF 自带的 `esp_http_server` 组件，监听 80 端口。
- **数据来源**：直接读取 `pet_tamagotchi` 的养成数据（阶段、亲密度、心情、相识天数等）。
- **页面形式**：单页 HTML，内嵌 CSS + JavaScript，无外部依赖。

## 三、对外接口（C 代码）

### 3.1 头文件 `web_server.h`

```c
#pragma once

#ifdef __cplusplus
extern "C" {
#endif

void web_server_start(void);   // 注册 WiFi 获得 IP 事件，之后自动启动 HTTP 服务
void web_server_stop(void);    // 如需关闭 Web 服务时调用（目前默认不调用）

#ifdef __cplusplus
}
#endif
```

### 3.2 启动时机（`desktop_pet.cc`）

在桌面宠物板级代码中，重写 `StartNetwork()`，保证 **WiFi 事件循环已经初始化** 后再注册 Web 服务器事件处理：

```c
void StartNetwork() override {
    WifiBoard::StartNetwork();   // 先按原逻辑启动 WiFi
    web_server_start();          // 然后注册 IP 事件，等拿到 IP 后自动启动 HTTP 服务器
}
```

这样可以避免在构造函数太早调用 `esp_event_handler_register` 导致注册失败、服务器无法启动的问题。

## 四、HTTP 服务器实现概览（`web_server.cc`）

### 4.1 关键点

- 使用 `httpd_start()` 启动服务器，端口默认为 **80**。
- 最大连接数、任务栈大小、优先级均做了下调，尽量减小对 LVGL 绘制和音频等任务的影响：
  - `max_open_sockets = 2`
  - `stack_size = 4096`
  - `task_priority = 1`（最低优先级）
- 只注册 3 个 URI：
  - `GET /`：返回内置的 HTML 页面。
  - `GET /api/pet_state`：返回宠物当前状态 JSON。
  - `POST /api/action?type=...`：根据 `type` 执行简单动作（摸头、戳脸、重置）。

### 4.2 WiFi 获取 IP 后自动启动

```c
static void on_got_ip(void *arg, esp_event_base_t base,
                      int32_t event_id, void *event_data) {
    (void)arg;
    do_start_httpd();  // 真正启动 HTTP 服务器
    esp_event_handler_unregister(IP_EVENT, IP_EVENT_STA_GOT_IP, &on_got_ip);
}

void web_server_start(void) {
    esp_event_handler_register(IP_EVENT, IP_EVENT_STA_GOT_IP,
                               &on_got_ip, nullptr);
    ESP_LOGI(TAG, "Will start after WiFi connected");
}
```

- 不再做静态 IP 配置，完全依赖路由器的 DHCP 分配地址。
- 设备连上 WiFi、拿到 IP 后，会打印日志并启动 HTTP 服务。

## 五、网页与接口说明

### 5.1 访问方式

1. 设备烧录并启动后，打开串口监视器，等待设备连接 WiFi。
2. 串口会打印类似日志（示例）：
   ```text
   I (10123) esp_netif_handlers: sta ip: 172.20.147.57, mask: 255.255.255.0, gw: 172.20.147.181
   I (10123) WifiStation: Got IP: 172.20.147.57
   I (10123) web_server: Web server started on: http://172.20.147.57/
   ```
3. 确保手机 / 电脑 和设备在同一 WiFi 下，在浏览器输入：
   - `http://172.20.147.57/`（以实际 IP 为准）

### 5.2 页面功能

内置 HTML 页面主要展示：

- **成长阶段**：陌生 / 熟悉 / 亲密（用 3 个圆点表示当前阶段）。
- **亲密度条**：0-100，取自 `PetData.intimacy`。
- **心情条**：0-100，取自 `PetData.mood`。
- **相识天数**：取自 `PetData.age_days`。
- **操作按钮**：
  - `模拟摸头`
  - `模拟戳脸`
  - `重置数据`

页面通过 JavaScript 每隔 **5 秒** 调用 `/api/pet_state` 更新界面。

### 5.3 JSON 状态接口：`GET /api/pet_state`

返回示例：

```json
{
  "stage": "熟悉",
  "stage_id": 1,
  "intimacy": 45,
  "intimacy_max": 100,
  "daily_intimacy": 3,
  "mood": 82,
  "mood_text": "开心",
  "age_days": 5
}
```

字段含义：

- `stage` / `stage_id`：当前成长阶段及其枚举值（0 陌生 / 1 熟悉 / 2 亲密）。
- `intimacy`：当前阶段亲密度（0-100）。
- `intimacy_max`：亲密度上限（目前固定 100）。
- `daily_intimacy`：今日已获得亲密度，用于递减收益和每日上限。
- `mood` / `mood_text`：当前心情数值与对应文案。
- `age_days`：相识天数。

### 5.4 动作接口：`POST /api/action?type=...`

支持的 `type`：

- `type=pat`：调用 `pet_on_pat()`，并通过 `Application::TriggerPetInteraction("摸头")` 触发一次完整的语音互动，等同于设备上的“摸头”事件。
- `type=poke`：调用 `pet_on_poke()`，并通过 `Application::TriggerPetInteraction("戳脸")` 触发一次完整的语音互动，等同于屏幕上的“戳脸”事件。
- `type=reset`：调用 `pet_reset()`，清空养成数据（不触发语音）。

也就是说，**在网页上点击“模拟摸头/模拟戳脸”和真实摸头/戳脸走的是同一条语音链路**：  
都会打开音频通道 → 切换到聆听状态 → 注入对应唤醒词（"摸头"/"戳脸"）→ 由云端返回语音回应。

HTTP 返回简单的 JSON 或文本，表示请求是否成功（主要用于调试或前端判断）。

## 六、设计考虑与性能影响

- **资源占用**：
  - 降低了 HTTP 任务优先级、栈大小、最大连接数，对 LVGL 绘制和音频任务影响较小。
  - 没有使用大体积外部库，页面完全内嵌在固件中。
- **稳定性**：
  - 服务随 WiFi 连接自动启动；如果需要，可以调用 `web_server_stop()` 主动关闭。
  - 仅暴露只读状态和简单动作，不直接操作底层硬件外设。
- **网络配置**：
  - 使用 DHCP 获取 IP，避免静态 IP 配置带来的兼容性问题。
  - 用户通过串口日志获取当前 IP 地址后，用浏览器访问。

## 七、如何调试与扩展

1. **调试步骤**：
   - 确认串口日志中出现 `Got IP` 和 `web_server` 启动日志。
   - 在浏览器访问 `http://设备IP/`，观察是否正常显示页面。
   - 打开浏览器开发者工具（F12），查看 `/api/pet_state` 和 `/api/action` 的网络请求是否 200。
2. **常见问题**：
   - 页面打不开：检查设备和手机是否在同一局域网；确认 IP 是否输入正确。
   - 数据不刷新：检查 `/api/pet_state` 是否能被访问；确认设备未掉线。
3. **扩展方向**（示例）：
   - 增加更多动作按钮（比如“喂食”、“送礼物”），在 `/api/action` 中分支处理。
   - 在页面上展示更多细节（例如今日互动次数、随机事件日志等）。
   - 使用简单的前端图表库（如纯 JS 绘制）显示心情 / 亲密度变化曲线（注意代码体积）。
