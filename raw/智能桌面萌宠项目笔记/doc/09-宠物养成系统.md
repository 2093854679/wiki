# 宠物养成系统（Tamagotchi）

## 一、功能概述

在 AI 桌面宠物的基础上，新增一套轻量"养成"机制，让宠物能随着与用户的互动逐渐变得更亲密。
核心特性：

| 特性       | 说明                                                             |
| -------- | -------------------------------------------------------------- |
| 亲密度成长    | 摸头/对话/投喂增加亲密度（递减收益 + 10 分钟冷却仅作用于摸头/对话），每日总上限 30 点，存入 NVS 断电不丢失 |
| 成长阶段     | 陌生 → 熟悉 → 亲密，每阶段亲密度 0-100，满 100 自动升段归零                         |
| 心情系统     | 0-100 的心情值随互动上升，每 5 分钟自动 -1（最低 20），每天向 50 回归                   |
| 主动呼唤     | 空闲超过 30 分钟自动发起对话（"你好久没理我了"）                                    |
| 早晚问候     | 每天 6-8 点早安、20-22 点晚安，每段时间只问候一次（依赖 SNTP）                        |
| 相识天数     | 每日跨日自增，记录养成了多少天                                                |
| MCP 状态查询 | AI 通过 `self.pet.get_state` 工具主动获取实时宠物状态，用于个性化回应                |

## 三、数据结构

```c
// pet_tamagotchi.h
typedef enum {
    PET_STAGE_STRANGER = 0,   // 陌生
    PET_STAGE_FAMILIAR = 1,   // 熟悉
    PET_STAGE_INTIMATE = 2,   // 亲密（最高阶段）
} PetStage;

typedef struct {
    int32_t gold;            // 金币余额（0–9999，用于商店购买）
    int32_t intimacy;        // 当前阶段亲密度 0-100，满100升段归零
    int32_t stage;           // 当前关系阶段 0=陌生/1=熟悉/2=亲密
    int32_t mood;            // 心情 0-100
    int32_t age_days;        // 相识天数
    int32_t last_date;       // 上次记录日期 YYYYMMDD
    int32_t last_greet_h;    // 上次问候时间（小时，-1=未问候）
    int32_t daily_intimacy;  // 今日已获亲密度（递减收益控制）
} PetData;
```

所有字段通过 `Settings` 类（NVS 命名空间 `"pet"`）持久化，设备掉电数据不丢失。

## 四、公开接口

## 五、接入方式

### 5.1 初始化（`desktop_pet.cc`）

在 `DesktopPetBoard` 构造函数中，SD 卡和摸头传感器初始化完成后调用：

```cpp
pet_init();   // 养成系统：从 NVS 恢复状态
```

### 5.2 每秒定时器（`desktop_pet.cc`）

添加 `InitializePetTimer()` 方法，使用 `esp_timer` 每 1 秒触发一次：

```cpp
void InitializePetTimer() {
    esp_timer_create_args_t args = {
        .callback = [](void*) {
            const char* text = pet_on_tick();
            if (text) {
                Application::GetInstance().TriggerPetInteraction(text);
            }
        },
        .arg = nullptr,
        .dispatch_method = ESP_TIMER_TASK,
        .name = "pet_tick",
        .skip_unhandled_events = true,
    };
    esp_timer_create(&args, &pet_tick_timer_);
    esp_timer_start_periodic(pet_tick_timer_, 1000000ULL);  // 1 s
}
```

`pet_on_tick()` 内部处理：
- 每天日期变更 → `age_days++`，心情向 50 回归，重置问候标记
- 早（6-8 点）/ 晚（20-22 点）→ 返回问候语，每段时间仅触发一次
- 空闲 ≥ 1800 秒 → 返回主动呼唤语，并轮换不同话术

### 5.3 对话完成回调（`board.h` + `desktop_pet.cc`）

在 `Board` 基类新增虚方法（默认空实现，不影响其他板型）：

```cpp
// board.h
virtual void OnChatCompleted() {}
```

`DesktopPetBoard` 重写该方法：

```cpp
// desktop_pet.cc
void OnChatCompleted() override { pet_on_chat(); }
```

在 `application.cc` 的 `tts/stop` 处调用：

```cpp
// application.cc — tts/stop handler
Schedule([this]() {
    if (GetDeviceState() == kDeviceStateSpeaking) {
        Board::GetInstance().OnChatCompleted();  // 养成系统感知对话完成
        // ... 原有状态切换逻辑 ...
    }
});
```

### 5.4 摸头事件（`touch.cc`）

在 `send_touch_notification` 里，调用 `TriggerPetInteraction` 之前：

```cpp
pet_on_pat();   // 养成系统：亲密度 +递减收益，心情 +2
Application::GetInstance().TriggerPetInteraction(text);
```

### 5.5 戳脸事件（`ui_pet.cc`）

在 `poke_face_cb` 里：

```cpp
pet_on_poke();   // 养成系统：心情 +1（不加亲密度）
Application::GetInstance().TriggerPetInteraction("戳脸");
```

### 5.6 宠物状态传递方式

> ⚠️ **注意**：早期曾将 `pet_state` 写入 `hello` 消息，但小智云服务端不会将自定义字段注入 system prompt，该方案已废弃。

当前正式方案：注册 MCP 工具 `self.pet.get_state`（见第 11.7 节），AI 在收到"摸头"/"戳脸"等触发词时主动调用，返回当前宠物状态文本，再据此生成个性化回应。

服务端角色介绍中须配置强制规则（见第十三节），保证 AI 稳定触发工具调用。

## 七、成长阶段与数值变化

### 阶段划分

V2 使用 `stage` 字段标记阶段，`intimacy` 表示当前阶段内的 0-100 进度：

```
stage=0（陌生）：intimacy 0→100，满100 → stage=1，intimacy归零
stage=1（熟悉）：intimacy 0→100，满100 → stage=2，intimacy归零
stage=2（亲密）：intimacy 0→100，满格后不再升段，继续积累
```

### 数值变化表

| 事件 | 亲密度 | 心情 | 金币 | 备注 |
|------|--------|------|------|------|
| 摸头（`pet_on_pat`） | +compute_gain() | +2 | +5 | 受 10 分钟 CD 与每日 30 点上限约束 |
| 戳脸（`pet_on_poke`） | 0 | +1 | +2 | 轻互动，只影响心情与金币 |
| 对话完成（`pet_on_chat`） | +compute_gain() | +1 | +15 | 同上 |
| 投喂（`pet_feed`） | +1 | +3 | 商店扣费 | 计入每日 30 点上限，不受 10 分钟 CD 约束 |
| 每 5 分钟 | 0 | -1 | 0 | 心情最低降至 20 |
| 每天跨日（SNTP） | 0 | 回归中间值 | +100 | daily_intimacy 重置 |
| 升段（陌生→熟悉） | 归零 | — | +200 | 一次性 |
| 升段（熟悉→亲密） | 归零 | — | +400 | 一次性 |

所有数值均被夹持（亲密度 0-100，心情 0-100），任何互动都会重置空闲计时器。

## 八、主动触发逻辑

`pet_on_tick()` 的决策优先级（由高到低）：

1. **当天早/晚问候**（SNTP 已同步时）
   - 早上 6-8 点，且 `last_greet_h != 当前小时` → 返回早安语
   - 晚上 20-22 点，且 `last_greet_h != 当前小时` → 返回晚安语
2. **空闲呼唤**
   - 连续空闲 ≥ 1800 秒（30 分钟）→ 轮换返回主动话术
3. **无触发** → 返回 `nullptr`

问候与呼唤触发后，均会重置 `s_idle_sec = 0`，避免连续触发。

## 十一、养成系统 V2：递减收益 + 阶段升级

### 11.1 设计动机

旧版亲密度为单一累计值（上限 200），每次互动固定加分，导致：
- 进度条视觉上永远只有 16%（166/999 时期）
- 心情因增量太大始终卡在 100
- 没有"升级"的成就感

V2 改为 **per-stage 0-100 + 升段机制 + 每日递减收益**。

---

### 11.2 新数据结构

```c
typedef struct {
    int32_t gold;            // 金币余额 0–9999（商店购买用）
    int32_t intimacy;        // 当前阶段亲密度 0-100，满100升段归零
    int32_t stage;           // 关系阶段：0=陌生 1=熟悉 2=亲密
    int32_t mood;            // 心情 0-100
    int32_t age_days;        // 相识天数
    int32_t last_date;       // 上次记录日期 YYYYMMDD
    int32_t last_greet_h;    // 上次问候时间（小时）
    int32_t daily_intimacy;  // 今日已获亲密度（递减收益控制）
} PetData;
```

NVS 键：`gold`、`stage`、`daily_int`、`last_gain_ts`（亲密度冷却时间戳）等，见第六节。

---

### 11.3 递减收益与冷却算法

```c
#define DAILY_INTIMACY_CAP  20   // 每日最多获得 20 点亲密度（摸头/对话）
#define INTIMACY_CD_SEC     600  // 亲密度增长冷却：10 分钟内最多获得一次

static int compute_gain(void) {
    int d = s_data.daily_intimacy;
    if (d >= DAILY_INTIMACY_CAP) return 0;   // 今日已满额
    // 10 分钟 CD：距上次获得亲密不足 600 秒则返回 0
    if (now - s_last_gain_time < INTIMACY_CD_SEC) return 0;
    int gain = 3 - d;
    if (gain < 1) gain = 1;
    if (d + gain > DAILY_INTIMACY_CAP) gain = DAILY_INTIMACY_CAP - d;
    s_last_gain_time = now;
    return gain;
}
```

- **冷却**：上次通过摸头/对话获得亲密度后 600 秒（10 分钟）内，再次摸头或对话完成不会增加亲密度。
- **递减公式**：`gain = 3 - daily_intimacy`（最低 1），即前几次 3→2→1→1…，直至当日累计达到 20 点。

每日互动收益示意（上限 20 点，且每次需满足 10 分钟 CD）：

| 今日第几次有效加分 | 获得亲密度 | 今日累计 |
|------------------|-----------|---------|
| 第 1 次 | +3 | 3 |
| 第 2 次 | +2 | 5 |
| 第 3 次起 | +1 | … |
| 满 20 点后 | +0 | 不变 |

每日跨日时 `daily_intimacy` 与 `last_gain_ts` 逻辑重置，下一天重新计算。**投喂**（`pet_feed`）增加的亲密度不计入每日上限，也不受 10 分钟 CD 限制。

---

### 11.4 升段机制

```c
static void try_promote(void) {
    if (s_data.intimacy >= 100 && s_data.stage < 2) {
        s_data.stage++;
        s_data.intimacy = 0;   // 归零，进入下一阶段继续积累
    }
}
```

- 每次 `pet_on_pat()` / `pet_on_chat()` 加分后自动调用
- 阶段上限为 2（亲密），不会再升段，但亲密度继续在 0-100 内积累

---

### 11.5 互动收益汇总

| 操作 | 亲密度 | 心情 | 金币 | 备注 |
|------|--------|------|------|------|
| 摸头 | `compute_gain()` | +2 | +5 | 10 分钟 CD + 每日 20 点上限 |

## 十二、注意事项

1. **SNTP 时间同步**：早晚问候、每日跨日重置 `daily_intimacy`、心情回归均依赖 `time()` 返回值 > 1000000。未同步时这些逻辑跳过，心情仅靠每 5 分钟衰减自然下降。
2. **新文件编译**：`pet_tamagotchi.cc` / `ui_pet_status.cc` 通过 CMakeLists.txt 的 `file(GLOB ...)` 自动包含。添加新文件后需 `idf.py reconfigure`（或 `touch main/CMakeLists.txt`）让 cmake 重新扫描。
3. **接口兼容性**：`board.h` 新增的 `OnChatCompleted()` 默认为空实现，其他板型无需修改。
4. **listen/detect 长度限制**：服务端对 `listen/detect` 消息的 `text` 字段有长度限制，仅允许传短唤醒词（如"摸头"、"戳脸"）。宠物状态需通过 `self.pet.get_state` MCP 工具传递，不可拼接到 detect 文本中。
5. **MCP 工具触发率**：大模型不保证每次都调用 `self.pet.get_state`，需在角色介绍中写"强制规则"并将指令置于靠前位置，提高触发稳定性。
6. **C++ 初始化器限制**：不可在 C++ 文件中使用 C99 指定初始化器（`{ .field = value }`）初始化数组，会导致编译器误判大括号嵌套层级，引发"At global scope"编译错误。应改用 `lv_color_hex()` 宏或 `if/else` 赋值。
7. **NVS 旧数据兼容**：V2 新增了 `stage` 和 `daily_int` NVS 键。旧版固件升级后首次启动时这两个键不存在，`GetInt` 会返回默认值 0，行为正常，无需手动迁移。
8. **UI 亲密度显示格式**：状态页亲密度数值格式为 `X / 100`，不显示今日已获点数（已去除 `+X今日` 杂项文字）。进度条范围为 0-100，满格时触发升段动画（阶段圆点变色）。

### 13.2 为什么不能用 detect 传状态

`listen/detect` 是协议层用于传递唤醒词的消息，服务端对其文本长度有严格限制（仅允许短词如"摸头"、"戳脸"）。尝试传递长文本会被服务端拒绝并返回错误提示。

因此宠物状态只能通过两种方式让 AI 感知：
1. **静态方式**：在角色介绍中写明各阶段/心情的回应规则（AI 根据 `get_state` 结果匹配）
2. **动态方式**：注册 `self.pet.get_state` MCP 工具，AI 主动调用获取实时数值
