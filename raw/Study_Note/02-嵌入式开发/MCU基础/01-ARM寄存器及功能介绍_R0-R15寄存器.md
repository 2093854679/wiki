## 1. ARM寄存器组概述

ARM处理器一般共有 **37个寄存器**，其中包括：

- **31个通用寄存器**：包括PC（程序计数器）在内，都是32位的寄存器
- **6个状态寄存器**：都是32位的寄存器

### 1.1 寄存器分类

| 寄存器类型 | 数量 | 说明 |
|-----------|------|------|
| 通用寄存器 | 31个 | R0-R15，其中R15为程序计数器PC |
| 状态寄存器 | 6个 | 1个CPSR + 5个SPSR（对应不同异常模式） |

### 1.2 处理器模式

ARM处理器共有 **7种不同的处理器模式**：

1. **用户模式（User）** - 非特权模式，运行用户程序
2. **快速中断模式（FIQ）** - 用于快速中断处理
3. **普通中断模式（IRQ）** - 用于普通中断处理
4. **管理模式（Supervisor）** - 用于系统调用和软件中断
5. **数据访问中止模式（Abort）** - 用于内存访问异常
6. **未定义指令中止模式（Undefined）** - 用于未定义指令异常
7. **系统模式（System）** - 特权模式，与用户模式共享寄存器

## 2. 处理器模式与寄存器映射

在每一种处理器模式中，可见的寄存器包括：
- 15个通用寄存器（R0~R14）
- 一个或者二个状态寄存器
- 程序计数器（PC）

### 2.1 寄存器映射表

| 寄存器 | 用户模式 | FIQ模式 | IRQ模式 | 管理模式 | 中止模式 | 未定义模式 | 系统模式 |
|--------|----------|---------|---------|----------|----------|------------|----------|
| R0-R7 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| R8-R12 | ✓ | R8_fiq-R12_fiq | ✓ | ✓ | ✓ | ✓ | ✓ |
| R13 | R13_usr | R13_fiq | R13_irq | R13_svc | R13_abt | R13_und | R13_usr |
| R14 | R14_usr | R14_fiq | R14_irq | R14_svc | R14_abt | R14_und | R14_usr |
| R15 | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| CPSR | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ | ✓ |
| SPSR | - | SPSR_fiq | SPSR_irq | SPSR_svc | SPSR_abt | SPSR_und | - |

**说明**：
- ✓ 表示该模式下可访问
- 带下标的寄存器表示该模式下的独立物理寄存器
- 系统模式与用户模式共享相同的寄存器组

## 3. R0-R15寄存器详细功能

### 3.1 R0-R3：参数传递寄存器

**主要用途**：
- 子程序间传递参数
- 函数返回值存储
- 临时数据存储

**特点**：
- 在所有处理器模式下共享同一物理寄存器
- 被调用函数无需保存这些寄存器的值
- 如果调用函数需要再次使用，必须自行保存

### 3.2 R4-R11：局部变量寄存器

**主要用途**：
- 保存局部变量
- 在Thumb程序中，通常只能使用R4-R7来保存局部变量
- 函数内部临时计算

**特点**：

- 被调用函数如果使用了这些寄存器，必须在返回前恢复其值
- 在中断程序中，编译器会自动保护R4-R11

### 3.3 R12：内部调用暂时寄存器（IP）

**主要用途**：
- 子程序间scratch寄存器
- 过程链接胶合代码中的临时存储
- 交互操作胶合代码

**特点**：
- 被调用函数在返回前不必恢复R12
- 在过程调用之间可以用于任何用途

### 3.4 R13：堆栈指针（SP）

**主要用途**：
- 指向当前堆栈的顶部
- 堆栈操作的基础指针

**特点**：
- **不能用于任何其它用途**
- 每种处理器模式都有独立的R13寄存器
- 退出被调用函数时，SP的值必须与进入时相同
- 堆栈指针的独立性确保了不同模式下的堆栈隔离

### 3.5 R14：链接寄存器（LR）

**主要用途**：
- 保存子程序调用的返回地址
- 保存中断的返回地址
- 异常处理时的返回地址存储

**特点**：
- 执行BL（Branch with Link）指令时，当前PC值被存入R14
- 每种处理器模式都有**独立的R14寄存器**
- 如果保存了返回地址，可以在调用之间将R14用于其它用途
- 程序返回时必须恢复R14的值

### 3.6 R15：程序计数器（PC）

**主要用途**：
- 存储当前执行指令的地址
- 控制程序执行流程

**特点**：
- **不能用于任何其它用途**
- 由于ARM采用了流水线机制，读取PC的值时：
  - **ARM状态**：PC = 当前指令地址 + 8字节
  - **Thumb状态**：PC = 当前指令地址 + 4字节
- PC指向当前指令的下两条指令地址（ARM状态）

## 4. 程序状态寄存器CPSR详解

### 4.1 CPSR寄存器结构

CPSR（Current Program Status Register）是当前程序状态寄存器，包含以下字段：

| 位域 | 名称 | 说明 |
|------|------|------|
| [31:28] | 条件码标志 | N、Z、C、V标志位 |
| [27:8] | 保留位 | 保留，必须为0 |
| [7] | I位 | IRQ中断禁用位 |
| [6] | F位 | FIQ中断禁用位 |
| [5] | T位 | Thumb状态位 |
| [4:0] | 模式位 | 处理器模式选择 |

### 4.2 条件码标志详解

#### 4.2.1 N标志位（Negative）
- **含义**：负数标志
- **设置条件**：在结果是有符号的二进制补码情况下
  - 如果结果为负数，则N=1
  - 如果结果为非负数，则N=0

#### 4.2.2 Z标志位（Zero）
- **含义**：零标志
- **设置条件**：
  - 如果结果为0，则Z=1
  - 如果结果为非零，则Z=0

#### 4.2.3 C标志位（Carry）
- **含义**：进位/借位标志
- **设置条件**：
  - **加法指令**（包含比较指令CMN）：如果产生进位，则C=1；否则C=0
  - **减法指令**（包括比较指令CMP）：如果产生借位，则C=0；否则C=1
  - **移位操作**：C为移位操作中最后移出位的值
  - **其他指令**：C通常不变

#### 4.2.4 V标志位（Overflow）
- **含义**：溢出标志
- **设置条件**：
  - **加减法指令**：在操作数和结果是有符号的整数时
    - 如果发生溢出，则V=1
    - 如果无溢出发生，则V=0
  - **其他指令**：V通常不发生变化

### 4.3 CPSR与SPSR的关系

- **CPSR**：当前程序状态寄存器，所有处理器模式下都可访问
- **SPSR**：保存程序状态寄存器，用于保存中断前的CPSR值
- **作用**：当异常出现时，SPSR用于保存CPSR的状态，以便异常返回后恢复异常发生时的工作状态

### 4.4 CPSR字段操作

#### 4.4.1 字段定义
```
CPSR有4个8位区域：
- F 标志域屏蔽字节(PSR[31:24])
- S 状态域屏蔽字节(PSR[23:16])
- X 扩展域屏蔽字节(PSR[15:8])
- C 控制域屏蔽字节(PSR[7:0])
```

#### 4.4.2 MSR指令示例
```assembly
MSR CPSR_c, #0xd3    ; 设置CPSR的控制域
MSR CPSR_f, R0       ; 设置CPSR的标志域
```

## 5. 寄存器使用约定

### 5.1 ARM-Thumb过程调用标准

根据"ARM-thumb过程调用标准"：

| 寄存器 | 用途 | 调用者保存 | 被调用者保存 |
|--------|------|------------|--------------|
| R0-R3 | 参数传递、返回值 | 否 | 否 |
| R4-R11 | 局部变量 | 是 | 是 |
| R12 | 内部调用暂时寄存器 | 否 | 否 |
| R13 | 堆栈指针 | 是 | 是 |
| R14 | 链接寄存器（LR） | 是 | 是 |
| R15 | 程序计数器 | - | - |

### 5.2 中断程序中的寄存器保护

**重要**：在中断程序中，所有的寄存器都必须保护，编译器会自动保护R4～R11。

### 5.3 PUSH指令中的寄存器保存规则

在ARM汇编中，`PUSH {R0-R3, LR}`指令只保存特定寄存器的原因：

#### 5.3.1 寄存器分类与保存责任

| 寄存器 | 分类 | 保存责任 | 在PUSH中的处理 |
|--------|------|----------|----------------|
| R0-R3 | 调用者保存 | 调用者负责 | 需要手动保存 |
| R4-R11 | 被调用者保存 | 被调用者负责 | 编译器自动处理 |
| R12 | 调用者保存 | 调用者负责 | 通常不需要保存 |
| R13(SP) | 特殊寄存器 | 硬件管理 | 由硬件自动管理 |
| R14(LR) | 调用者保存 | 调用者负责 | 需要手动保存 |
| R15(PC) | 特殊寄存器 | 硬件管理 | 通过LR间接保存 |

#### 5.3.2 详细说明

**R4-R11：编译器会自动处理，无需手动保存**
- 这些是被调用者保存寄存器
- 编译器在函数调用时自动添加PUSH/POP指令
- 被调用函数如果使用了这些寄存器，必须在返回前恢复

**R12：通常不需要保存，除非特殊用途**
- R12是调用者保存寄存器
- 被调用者可以随意使用，不需要保存
- 只有在特殊情况下（如中断处理）才需要手动保存

**R13（SP）：堆栈指针，由硬件自动管理**
- 堆栈指针由硬件自动维护
- 不能直接保存到堆栈中（会造成递归）
- 通过PUSH/POP指令间接管理

**R15（PC）：程序计数器，由硬件自动管理**
- 程序计数器不能直接保存
- 通过BL指令将PC+8保存到LR中
- 通过BX LR或MOV PC, LR恢复PC值

#### 5.3.3 实际应用示例

```assembly
; 示例1：普通函数调用
normal_function:
    ; 编译器自动添加：
    PUSH {R4-R11, LR}  ; 自动保存被调用者保存的寄存器
    ; 函数体
    POP {R4-R11, LR}   ; 自动恢复
    BX LR

; 示例2：中断处理程序
irq_handler:
    PUSH {R0-R3, LR}   ; 手动保存调用者保存的寄存器
    ; 中断处理代码
    POP {R0-R3, LR}    ; 手动恢复
    BX LR

; 示例3：完整的中断处理
complete_irq_handler:
    PUSH {R0-R12, LR}  ; 保存所有通用寄存器和LR
    ; 中断处理代码
    POP {R0-R12, LR}   ; 恢复所有寄存器
    BX LR
```

## 6. 实际应用示例

### 6.1 函数调用示例

```assembly
; 函数调用示例
main:
    MOV R0, #10        ; 第一个参数
    MOV R1, #20        ; 第二个参数
    BL add_function    ; 调用函数
    ; R0现在包含返回值

add_function:
    ADD R0, R0, R1     ; 计算 R0 + R1
    BX LR              ; 返回（R14中的地址）
```

### 6.2 中断处理示例

```assembly
; 中断处理程序
irq_handler:
    ; 保存寄存器（编译器自动处理R4-R11）
    PUSH {R0-R3, LR}
    
    ; 中断处理代码
    ; ...
    
    ; 恢复寄存器
    POP {R0-R3, LR}
    BX LR              ; 返回
```

### 6.3 模式切换示例

```assembly
; 切换到管理模式
MRS R0, CPSR          ; 读取当前CPSR
BIC R0, R0, #0x1F     ; 清除模式位
ORR R0, R0, #0x13     ; 设置为管理模式
MSR CPSR_c, R0        ; 写入CPSR控制域
```

## 7. 总结

ARM处理器的寄存器组织是其架构的核心，理解各寄存器的功能和使用约定对于：

- **高效编程**：正确使用寄存器可以提高代码效率
- **调试分析**：理解寄存器状态有助于问题定位
- **系统设计**：合理利用不同模式的寄存器组
- **性能优化**：减少不必要的寄存器保存和恢复

通过深入理解R0-R15寄存器的功能和使用方法，开发者可以编写出更加高效和可靠的ARM汇编代码。
