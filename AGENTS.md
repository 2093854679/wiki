# LLM Knowledge Base — Codex Integration

This vault is an LLM-powered knowledge base. Raw source documents live in `raw/`,
the compiled wiki lives in `wiki/`. Everything is managed via the `kb` CLI.

## Key directories

- `raw/` — Source documents (articles, papers, repos, datasets, images). You read these but rarely edit them.
- `wiki/summaries/` — Per-document summaries generated from raw files.
- `wiki/concepts/` — Concept articles extracted and synthesized from raw documents.
- `wiki/outputs/` — Generated outputs: Q&A answers, Marp slides, matplotlib charts.
- `wiki/index.md` — Master index auto-generated by `kb index`.

## Auto-ingest rule (CRITICAL)

**Every time this conversation starts, or the user says "处理一下" / "有新内容" / "更新wiki" / "编译"**
you MUST execute this exact sequence:

1. `python -m kb ingest` — scan raw/ for new/changed files
2. If new/changed markdown files exist: read them, write summaries to `wiki/summaries/`, extract concepts to `wiki/concepts/`, then `python -m kb index`
3. Run `python -m kb stats` to confirm

Never wait for the user to ask twice. The raw/ directory is the trigger — new content there means
the wiki needs updating. You are the LLM compiler, so do the compilation directly
(do NOT call `python -m kb compile` — that requires an external API key; you ARE the LLM).

## Common workflows

### Ingesting new raw documents
1. User adds files to `raw/`.
2. Run `python -m kb ingest` to see what's new.
3. Read new/changed files and write summaries to `wiki/summaries/`.
4. Extract cross-cutting concepts to `wiki/concepts/`.
5. Run `python -m kb index` to rebuild the master index.

### Answering a question against the wiki
Use `python -m kb query "the question"` which will:
- Search the wiki for relevant articles
- Read them into context
- Answer the question
- Optionally render output as markdown (default), Marp slides (`--format slides`), or matplotlib chart (`--format chart`)

You can also answer questions directly: read `wiki/index.md` to find relevant articles, read those articles, then write your answer to `wiki/outputs/`.

### Health check / Linting
Run `python -m kb lint --check consistency|gaps|suggestions` to find:
- Inconsistent data across articles
- Missing topics or data gaps
- Interesting cross-connections for new articles

### Enhancing the wiki
When you answer a question or discover something new, file the output back into the wiki:
- Good Q&A answers → `wiki/outputs/` (then optionally promote to `wiki/concepts/`)
- New insights → Write a new concept article in `wiki/concepts/`
- Cross-links discovered → Update `[[wikilinks]]` in relevant articles

## Wiki Conventions
- Use `[[wikilinks]]` for internal links (Obsidian format)
- Concept articles should have a `## Related` section with backlinks
- Summaries should link to their source file in `raw/`
- Every concept article needs a brief TLDR at the top

## Templates
Jinja2 templates in `tools/kb/templates/` define the structure for generated content.
Use `kb render` to apply a template to data.
